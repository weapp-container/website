# React Native SDK integration

[简体中文](react-native.md) · **English**


The React Native package exposes the native session controller to TypeScript through TurboModule and hosts the native screen through the Fabric view.

<a id="requirements"></a>
<a id="从当前源码准备原生依赖"></a>
## Prepare native dependencies from current source code

First build Android/iOS or the corresponding Desktop SDK from the public core repository and fixed SDK submodules, and regenerate the local reviewed manifest. The framework wrapper will verify the native archive and installation receipt, and will not implicitly download historical binaries with unknown matches. [Build from source](/en/docs/engineering/weapp-container/docs/sdk-source-build/) provides complete packaging, offline preparation and framework building sequence. The following example uses the local SDK generated by this process.

<a id="create-view"></a>
<a id="1-安装-sdk"></a>
## 1. Install SDK

Using React Native 0.88.0 new architecture, React 19.3.x and TypeScript 5.9.3. Native targets are Android API 26+ and iOS 16+; Android apps only enable `arm64-v8a` and `x86_64`.

When there is an SDK distribution package with native dependencies, install the local archive in the React Native application:

```bash
npm install /absolute/packages/weapp-container-react-native-0.1.0-preview.6.0.tgz
cd ios
pod install
```

Put `hello-pack/` into Android's `android/app/src/main/assets/hello-pack/`, or add it as a complete resource folder to the iOS target. For SDK archive acquisition and source code packaging, see [React Native SDK README](https://github.com/weapp-container/sdk-react-native/blob/main/README.en.md); the file name here does not mean that the npm registry has been released.

<a id="mount-load"></a>
<a id="2-创建-controller"></a>
## 2. Create Controller

Executed once by the initialization logic of the page or route, use state/ref to retain the instance:

```tsx
import {
  WeappContainerController,
  WeappContainerView,
  type ContainerEvent,
} from '@weapp-container/react-native';

const controller = await WeappContainerController.create({
  storage: {key: 'catalog/account-7'},
});
const unsubscribe = controller.subscribe((event: ContainerEvent) => {
  if (event.type === 'error') console.error(event.payload);
});
await controller.registerHostMethod('app.openProfile', async (payload) => ({
  profile: payload,
}));
```

<a id="3-挂载视图并加载"></a>
## 3. Mount the view and load it

Pass the retained Controller to the view in JSX:

```tsx
<WeappContainerView
  controller={controller}
  style={{height: 480, width: '100%'}}
  onSurfaceError={error => console.error(error.code, error.message)}
/>
```

Call loading after the view is mounted; the SDK waits for the effective layout of the native surface:

```typescript
await controller.load({asset: 'hello-pack'});
```

When the page owner finishes using the session, await shutdown:

```typescript
unsubscribe();
await controller.flushStorage();
await controller.close();
```

React effect cleanup cannot return Promise, and the asynchronous closure should be handed over to the session management logic of the page; if the component has unmounted during creation, the new instance should be closed immediately after creation. For complete React mounting and closing processing, see [Example App.tsx](https://github.com/weapp-container/sdk-react-native/blob/main/example/App.tsx).

<a id="release-consumer"></a>
<a id="控制器-api"></a>
## Controller API

- `create(configuration)`: Use stable storage key or explicitly select memoryOnly.
- `registerHostMethod(name, handler)`: Register a host handler that does not occupy the `wx.` namespace. The handler receives an AbortSignal.
- `load(source, options)`: Load a verified pack from an absolute local directory or app assets.
- `subscribe(listener)`: Subscribe to ready, navigation, message, error, closed and presented events.
- `sendMessage`, `navigate`, `back`, `setForeground`, `state`, `capabilities`: Drive and observe sessions.
- `flushStorage` and `close`: Ensure that the native owner is closed after the status is written back.

<a id="构建-consumer"></a>
## Build a standalone consumer

**Version and release status**

`@weapp-container/react-native` source code is currently `0.1.0-preview.6.0`, using Apache-2.0. The SDK README records that the default runtime lock still points to the historical preview.5.3; when building from source code, you must explicitly use the audited preview.6.0 lock that matches the wrapper. The source code version does not mean that the npm release or runtime archive has been made public.

Release build runs TypeScript, React Native Codegen, and package file review. The standalone consumer consumes the full npm archive and pre-prepared native SDK and should not implicitly rely on the core runtime code within the workspace.

```bash
node tools/create-consumer.mjs \
  --package /absolute/path/authorized-sdk.tgz \
  --out /absolute/path/new-consumer
```

Successful consumer generation only proves that the specified package and project have been prepared. Independent Android/iOS compilation, GPU rendering, real device lifecycle and release signature are recorded separately.
