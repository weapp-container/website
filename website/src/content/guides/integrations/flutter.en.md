# Flutter SDK integration

[简体中文](flutter.md) · **English**


`weapp_container` provides a controller owned by your application and a widget that embeds the native view in a Flutter layout.

<a id="platforms"></a>
<a id="从当前源码准备原生依赖"></a>
## Prepare native dependencies from current source code

First build Android/iOS or the corresponding Desktop SDK from the public core repository and fixed SDK submodules, and regenerate the local reviewed manifest. The framework wrapper will verify the native archive and installation receipt, and will not implicitly download historical binaries with unknown matches. [Build from source](/en/docs/engineering/weapp-container/docs/sdk-source-build/) provides complete packaging, offline preparation and framework building sequence. The following example uses the local SDK generated by this process.

<a id="controller"></a>
<a id="1-添加-sdk-依赖"></a>
## 1. Add SDK dependency

The current platform matrix of the repository refers to Flutter 3.47.7. Native SDK targets Android API 26+, iOS 16+, and macOS 12+. Windows/Linux also requires the exact native distribution and a matching CMake/GTK/OpenGL backend verified on the target system. Dependent sources include platform federated packages under the same checkout; if migrating directories, please keep these local relative paths to packages together.

```yaml
dependencies:
  weapp_container:
    path: /absolute/path/sdk-flutter/weapp_container
```

Local checkout and npm/pub registry release are not the same thing; only the audited runtime and license archive should be included in the distributable SDK.

For installation and native dependency preparation, see [Flutter SDK README](https://github.com/weapp-container/sdk-flutter/blob/main/README.en.md). Unpack `hello-pack/` to a local directory readable by the application; please refer to [Complete Example](https://github.com/weapp-container/sdk-flutter/blob/main/example/lib/main.dart) for the implementation of copying package files from Flutter assets.

<a id="mount-load"></a>
<a id="2-创建-controller"></a>
## 2. Create Controller

Create the controller once in page initialization. Retain it and its event subscription; do not create them inside `build()`:

```dart
import 'package:weapp_container/weapp_container.dart';

final controller = await WeappContainerController.create(
  storageKey: 'account-42:catalog',
);
await controller.registerHostMethod('host.echo', (call) async {
  call.cancellation.throwIfCancelled();
  return {'value': call.payload};
});
final subscription = controller.events.listen((event) {
  if (event.type == 'message') debugPrint(event.toString());
});
```

<a id="api"></a>
<a id="3-挂载-widget-并加载"></a>
## 3. Mount the Widget and load the pack

Use the already created Controller in `build()` of the page:

```dart
SizedBox(
  height: 480,
  child: WeappContainerView(controller: controller),
);
```

After mounting the widget, call `load` from the initialization logic. The SDK waits for valid layout metrics:

```dart
await controller.load('/absolute/app-support/hello-pack');
```

When the page owner finishes using the session, await cleanup:

```dart
await subscription.cancel();
await controller.flushStorage();
await controller.close();
```

Widget unmounting and session closing are handled separately; when the page exits during creation, the Controller that returns later must also be released. `setForeground` is called when the page is hidden or restored. For complete owner implementation, see the example above.

<a id="validation"></a>
<a id="主要-api"></a>
## Main API

- `WeappContainerController.create`: Select persistent storage key or explicitly request memory-only according to the supported platform.
- `registerHostMethod`: Register Future/FutureOr host method and cancel handling before load.
- `load`, `sendMessage`, `navigate`, `back`: Control app session and business messages.
- `setForeground`: Pass the application foreground and background state to the native host.
- `flushStorage`, `close`: Explicitly persist and retire native resources.
- `pendingHostLayout` and `acceptedHostLayout`: Observe layout protocols only when atomic host layout is selected; observing does not equal native acceptance.

<a id="平台验证"></a>
## Platform verification

**Version and Release Status**

The Flutter wrapper is currently `0.1.0-preview.6.0`, and the Flutter version is fixed at 3.47.7. There is currently no Windows entry for the runtime lock; there is still a mismatch in the Linux plug-in ABI. Dart type checking or a certain platform build pass does not mean that all plugins and GPU backends will work.

The Flutter repository maintains cross-platform packages and standalone examples. Run respective `prepare-native`, plugin build, example consumer and real device check based on currently available SDK pins; Windows/Linux desktop graphics and Flutter plugin ABI must be accepted on the target system itself.
