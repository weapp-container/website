# SDK warehouse and source code construction

[简体中文](/docs/engineering/weapp-container/docs/sdk-repositories/) · **English**


The core runtime and SDK’s own source code adopts Apache-2.0, and individually identified dual-license crates and third-party components retain their original licenses. The SDK continues to be maintained independently, and the main repository combines them via an HTTPS submodule that fixes commits.

| Warehouse | Path | Content |
| --- | --- | --- |
| [sdk-contract](/en/docs/engineering/sdk-contract/index/) | `sdk/contract` | C ABI, TypeScript types and protocols |
| [sdk-android](/en/docs/engineering/sdk-android/index/) | `sdk/android` | Kotlin / JNI / Gradle |
| [sdk-ios](/en/docs/engineering/sdk-ios/index/) | `sdk/ios` | Swift / UIKit / SwiftPM / CocoaPods |
| [sdk-desktop](/en/docs/engineering/sdk-desktop/index/) | `sdk/desktop` | C / C++ / CMake |
| [sdk-flutter](/en/docs/engineering/sdk-flutter/index/) | `sdk/flutter` | Flutter platform plug-in |
| [sdk-react-native](/en/docs/engineering/sdk-react-native/index/) | `sdk/react-native` | Fabric / TurboModule |

`website` corresponds to the documentation and display warehouse, and the runtime distribution tool is located in [tools/runtime-artifacts](/en/docs/engineering/weapp-container/tools/runtime-artifacts/index/) of the main warehouse. The old `runtime-artifacts` warehouse only retains read-only historical archives and is no longer used as a submodule or new release entry. `vendor/weapp-vite` is pinned to the reviewed upstream commit.

<a id="当前源码构建"></a>
## Current source code build

First complete the dependency installation of the root directory README. Build the runtime from the current main repository and do not require historical download credentials. Native SDK example for Apple Silicon macOS:

```sh
pnpm sdk:build:native -- --target aarch64-apple-darwin --profile release
pnpm sdk:licenses -- --target aarch64-apple-darwin
```

Ubuntu’s Skia precompilation cache may not cover the current feature combination; install system dependencies before compiling from source:

```sh
sudo apt-get update
sudo apt-get install -y clang libclang-dev ninja-build pkg-config python3 libfontconfig1-dev libfreetype6-dev libgl1-mesa-dev libegl1-mesa-dev fonts-dejavu-core
```

CI performs the same preparation via a shared Linux native dependency action, without relying on the runner image happening to carry development headers.

Release-level native builds require clean, committed source code, with commit, feature, platform and product hashes recorded. See `scripts/lib/sdk-native-features.mjs` and [Platform Archive Description](/en/docs/engineering/weapp-container/docs/platform-runtime-artifacts/) for other targets.

The entrances to each platform are `pnpm sdk:build:android`, `pnpm sdk:build:ios`, `pnpm sdk:build:desktop`, `pnpm sdk:build:flutter` and `pnpm sdk:build:react-native`. Select parameters according to the corresponding SDK README, and explicitly pass in the matching new build runtime or installation directory. The standalone SDK does not implicitly look for parent repositories, nor does it silently fall back to old archives.

<a id="预编译包和兼容性"></a>
## Precompiled packages and compatibility

The existing lock file records the version, ABI, platform, size and SHA-256 of the historical archive. These values ​​and strict validation are retained, and the access requirements and accompanying licenses for historical downloads remain intact. The downloader is only compatible with the nine historical versions of the old warehouse and does not allow subsequent versions to use the old warehouse.

The updated downloader accurately maps `weapp-container/runtime-artifacts` in the old lock to
`weapp-container/runtime-artifacts-private-archive`, the receipt records both the original identification and the actual repository.
No cross-warehouse rollback. Legacy downloaders and hard-coded URLs need to be upgraded; the new repository with the same name does not host historical binaries.

The new manifest is generated by the main repository and points to the exact `runtime-v<版本>` of `weapp-container/weapp-container`. Use `pnpm runtime:package` for packaging, `pnpm runtime:verify` for offline verification, and then press [Release Tool Instructions](/en/docs/engineering/weapp-container/tools/runtime-artifacts/index/) to execute `pnpm runtime:publish`. The publisher refuses to overwrite existing tags or assets. The independent SDK uses `--manifest` to explicitly select the new audited list, the download receipt records the actual warehouse, and there is no cross-warehouse rollback.

The source code and release process migration does not re-release the native binary; the old lock repository cannot be changed to the core repository and the hash can be reused. The core source code repository is now public, private historical binaries still require archive read permission; the Apache-2.0 source code license does not relicense old archives.

Before archiving, it was found that some old default pins were inconsistent with the remote assets of the same name. For details, see [Historical Pin Audit](/en/docs/engineering/weapp-container/docs/runtime-artifacts-migration/). These downloads continue to fail and remain verified; matching source code should be built upon access, or a verified package list should be explicitly selected.

Keep C ABI `1`, existing package names and public types. Optional protocol extensions continue to query capability versions. `ORIGIN.json` retains the historical source, and subsequent modifications use the `SOURCE-INVENTORY.json` refresh tool of each SDK to record the current source code.

First verify and submit in the corresponding SDK, and then update the main warehouse pointer. The Git history of the public SDK remains continuous, and the old private fetch history is kept in the private archive.
