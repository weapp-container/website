## Implemented DOM Transaction Boundaries

Base DOM `button` adapter has been added: native button, restricted appearance properties, subtree preservation, disabled ancestor input barrier, loading and basic ARIA; host special capabilities are still explicitly denied. Implementation boundaries with the Node contract are detailed in [DOM button base adapter](dom-button.en.md). Specialized `--fixture button` has been integrated into controls at r6 via real browser native input and rebuild retirement validation; failures of historical fixtures remain unchanged.

The following shared boundary already has code and targeted validation entry points, does not imply that all WebView capabilities or host acceptance has been completed:

1. DOM reuses pre-evaluated templates and component documents, skipping Rust WXSS cascading, image rasterization caching, Taffy layout, Skia page commit, and pixel readback. It still executes the real View program and cannot be replaced by a static DOM fixture.
2. Independent `PresentationKey` binds session, page, document revision, presentation revision, surface generation, and profile; the u64 in the protocol uses decimal strings. Preparation, licensing, browser submission, and final ACK are separated; HTTP queue receipts cannot prematurely trigger ready or open input.
3. Runtime builds an authoritative event topology from pre-evaluated `ViewDocument`; browser submission provides occurrence target, coordinates, touch points, and other facts, without specifying handler, propagation path, or component owner. Batches are first validated; navigation and data side effects of each event take effect before subsequent events.
4. `view.geometry` stores the browser's actual layout, validates the complete occurrence set and epoch. DOM SelectorQuery provides an asynchronous partial implementation negotiated with explicit recipient, verified against corresponding native regressions and controls r6 real browser fixture; query measurement watermarks and input geometry authorization are separately validated and do not equate to full WeChat SelectorQuery compatibility. IntersectionObserver and scroll command adapter remain explicitly unsupported. Media queries use host-effective logical width and height; it does not wait for DOM's first frame or read old Skia geometry.
5. Pending/accepted documents and resources are retained per transaction; changes to manifest, resize, page, and app lifecycle revoke old authorizations. Side effects from components/JS that occurred during preparation are not committed for rollback; old views can be retained, but failed inputs must be blocked. Page `inputEnabled:false` does not equate to interaction acceptance.
6. Content-addressed images are transmitted via a separate resource interface using the full `PresentationKey` and declared SHA-256 authorization; internal scripts or style blobs are not exposed to the browser merely because they know the hash. The transmission end still must independently enforce resource budget, late requests, and connection cleanup rules.

At runtime, `BrowserPageInput` is captured when copying root page data and is retained alongside candidate and presented documents; it is independent of `ViewDocument.revision`. A simulator is developed to determine, based on this actual consumption version, whether further redrawing is needed: redrawing after touch cancellation is correctly recorded, and subsequent component and ready writes will still trigger the next round. Explicit `render.data`, development preview, and different logic viewports do not pretend to be the automatically rendered result of the current page. Snapshots are only local scheduling information and cannot substitute a presentation license, visibility lease, or asynchronous geometric authorization.

Media queries retain registration of shared observers, batched callbacks, and lifecycle agreements; subscriptions are preserved when the page is hidden, allowing continued reception of host logic size changes. Upon component destruction, page unloading, or explicit disconnect, cleanup occurs. Waiting persists when no valid host size is available; scaling factors, DPR, and display scaling are not considered changes in logic size. This behavior still does not equate to official acceptance.

Transactions, cancellation, late ACKs, resource release, and slow-channel failures are managed by dedicated testing. Actual browser smoke `passed` is limited to the source code/binary bound to the report and the executed checks; unobserved lifecycle, effective image transmission, continuous scrolling, or performance behavior cannot be inferred from a single click result.
