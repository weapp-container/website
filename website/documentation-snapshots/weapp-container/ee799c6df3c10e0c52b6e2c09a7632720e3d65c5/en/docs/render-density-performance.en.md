# Rendering Density, Frame Transmission and Diagnostics

[简体中文](render-density-performance.md) · **English**


This fix separates the maintenance of logical layout, physical target, and CPU pixel acquisition:

- Web, browser dev owner, and remote emulator auto density was previously capped at 2×. Now it uses actual display DPR, preserving 0 < DPR ≤ 4 and physical pixel budget; budget shortfall results in explicit failure, no silent degradation of clarity.
- Software rendering previously could not submit high-density targets. Now it rasterizes according to the accepted target's physical dimensions, geometry and clipping are transformed only once, logical layout, hit testing, and input coordinates remain unchanged. Density updates with unchanged size retain valid snapshots and ACK identity.
- SDK regular CPU frame acquisition previously returned full-frame clones. Now it caches `Arc<RenderSnapshot>` by revision and accepted target size, C ABI frame handles hold immutable shared pixels. Old handles remain valid after resize, next frame, and close; explicit compatibility with snapshot API still returns independent copies.
- Web external frame images previously passed through RGBA JSON arrays, then iteratively checked properties and copied to bytes. The new WASM export uses WCF1 (magic number, metadata length, layout JSON, contiguous RGBA), Worker validates resource count, size, range, and total budget, then transmits independent byte buffers. The old JSON API remains compatible, GPU regular presentation does not read full-frame pixels.
- CanvasKit's laid-out text previously invoked `getGlyphIDs` and `drawGlyphs` per glyph, crossing the JS/WASM boundary on every draw. Now each text node is mapped and submitted once, retaining absolute coordinates after layout; fractional origin and overlapping glyphs are resolved via real CanvasKit CPU pixel mapping. Integer and range of `Uint8Array` are guaranteed by type, and no longer checked byte-by-byte per frame; the old JSON array still checks all elements and gaps.

`renderDiagnostics` SDK command returns up to 120 frames' actual backend, mode, GPU attachment status, logical and physical dimensions, DPR, prepare/snapshot duration, and exact generation/revision of ACK waiting. Repeated or mismatched ACKs do not increase sample count. ACK intervals are not display refresh clocks; the command explicitly retains `scrollFps:null`, `droppedFrameRate:null`. The web new protocol additionally logs prepare/export time and `binary-rgba` or `json-rgba` transfer method, while Showcase performance report preserves raw samples.

Verification entry points include DPR/pixel edge regression when sharing a renderer, runtime initial and dynamic density testing, SDK shared pixel and old frame lifecycle testing, WCF1 damage scope testing, Worker actual MessagePort transmission and presentation transaction testing. Software and protocol testing do not prove actual device GPU frame rates; release evidence must separately record platform, actual backend, first frame, scrolling, and memory results.

Subsequent profile identifies invalid object allocations in ordinary frame metadata, as well as byte-by-byte comparison of image cache. The converter now creates replacement objects only when sub-value changes; aligned RGBA pixels are compared in 32-bit chunks, while unaligned and old arrays are compared byte-by-byte. A real Worker client issues a module-private, single-use ownership receipt after validation, and the session can consume existing frames; copies are still made for other sources, second consumers, and expired responses.

The Worker event/frame/ACK queue previously used nested zero-delay timers and was subject to the browser’s minimum delay. It now uses `scheduler.postTask` when supported, preserving real task boundaries, queue order, shutdown, and timer fairness. Unavailability or submission failure falls back to timers; tokens guarantee execution at most once. Sample sizes, two stable RAFs, and performance thresholds are unchanged.

The default wght of the Noto Sans SC variable font is 100, so the Web default instance renders Thin glyphs. `scripts/prepare-renderer-font.py` statically uses fonttools 4.60.1 to generate a Container Sans SC Regular at wght 400, preserving all 30,890 characters and OFL. Output size: 10,595,952 bytes, a 40.4% reduction compared to the original font; two generations produce consistent hashes, SHA-256: `916bd5146cd1099aff18931fd0c85f4f3fd1ff7b2c966cb3cc22a4e5a6216983`. The historical restricted native SDK still includes the original font, retaining the old hash and installation boundaries; this Web font replacement does not imply that the historical native package has been rebuilt.

Showcase historical production input p95 1116.7ms, frame RPC p95 736.5ms samples are available in the submodule `website/docs/showcase-performance.md`. Performance results from the new version shall be considered final as per the published report; performance gate passing cannot be directly inferred from the current source code optimizations.

`website/` is a submodule of the documentation and presentation repository, and the locked commit is obtained using `git submodule update --init website`; the release tooling is located in the core repository's `tools/runtime-artifacts/`. When installing the Website within the parent pnpm workspace, execute `pnpm --ignore-workspace install --frozen-lockfile`. The runtime must be rebuilt from a clean, committed codebase, publishing the exact source commit, product hashes, and license receipts; a staging acceptance must be completed and a rollback version archived prior to production deployment.


Native core artifacts can be independently packaged via `node scripts/dev-player-runtime-archives.mjs --runtime-root <inputs> --platform <platform> --runtime-only --out <fresh-output>`. The path still validates the complete architecture set, a clean source code commit, the original hash, license, offline unpacking, and all files; it does not require a previously rebuilt wrapper with unchanged code, nor does it generate records of wrappers that have already passed. Without `--runtime-only`, the original SDK distribution and consumer checks are retained.
