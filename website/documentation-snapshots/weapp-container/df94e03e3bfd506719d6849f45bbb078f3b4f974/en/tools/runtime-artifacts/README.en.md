# Runtime Distribution Tool

[简体中文](README.md) · **English**


Core repository maintains the packaging, offline validation, and GitHub Release publishing of native runtime and SDK. Tools and boundary tests have been migrated from `runtime-artifacts`'s `f50e26252b43c13ea68821154d5ebaaa40527b75`, with source code licensed under Apache-2.0. Node.js 24, Python 3, and GitHub CLI at release time are required environments; no additional npm dependencies are needed.

<a id="构建与打包"></a>
## Build and Packaging

Operations in the root directory of the core repository. First, build the native library from clean, committed source code and collect the target licenses, see [SDK Source Build](../../docs/sdk-repositories.en.md). The packager does not compile source code; all slices must have a consistent, complete source commit, successful build receipt, fixed header files, and complete license list.

```sh
pnpm runtime:package -- \
  --source-commit <40位完整源提交> \
  --native-root /absolute/native \
  --licenses-root /absolute/licenses \
  --out-dir /absolute/release \
  --target aarch64-apple-darwin
```

`--target` accepts explicit comma-separated targets; when omitted, it selects supported targets present in the input directory. SDK packages use `--component android-sdk|ios-sdk|desktop-sdk --platform <平台> --arch <架构> --install-dir <已验证安装目录>`; universal packages must also list their actual slices with `--architectures`. See `pnpm runtime:package -- --help` for all options.

Output includes `manifest.json`, `provenance.json`, `SHA256SUMS` and archive. Identical versions can have target additions made incrementally locally, but archives with the same name cannot change bytes. Version, ABI, and verified header/file/license hash values are located in [policy.json](policy.json), and tests will verify against core release versions and independent contract versions. Before generating a new release, these identities must first be reviewed.

<a id="验证与发布"></a>
## Verification and Release

```sh
pnpm runtime:verify -- \
  --contract-dir /absolute/sdk-contract \
  --release-dir /absolute/release \
  --work-dir /absolute/work \
  --report /absolute/offline-installation.json

# 默认只做本地验证和离线安装，不调用 GitHub。
pnpm runtime:publish -- --release-dir /absolute/release --notes-file /absolute/notes.md

# 从与生产收据一致的干净源码 checkout 显式发布。
pnpm runtime:publish -- --release-dir /absolute/release --notes-file /absolute/notes.md --execute

# Create and verify a full 14-archive draft; publish manually in GitHub.
pnpm runtime:publish -- --release-dir /absolute/release --notes-file /absolute/notes.md --execute --draft-only
```

The publisher only accepts the full native/SDK manifest generated by this packager; Web, Harmony, and restricted-showcase use their respective release and acceptance workflows. It freezes input bytes, re-verifies hashes, and performs offline installation, rejects existing releases/tags, then creates a draft, uploads precise assets, validates server-side SHA-256 before publishing a prerelease without altering latest. On upload failure, the draft is retained for manual review; do not overwrite assets or retry with only a modified manifest. Future reuploads should use a new version and new build evidence.

New manifests record `weapp-container/weapp-container` and the exact `runtime-v<版本>`. Integrators download that release’s `manifest.json` and explicitly select it with the SDK’s `--manifest`. Source licensing and repository visibility are separate: private core repositories require a `WEAPP_CONTAINER_RUNTIME_TOKEN` with read access; publishing requires a GitHub CLI login with contents write access. SDKs also support anonymous access to public core releases.

`--draft-only` requires `--execute` and leaves the verified release unpublished. It requires all nine runtime and five SDK archives. The default command remains local-only; `--execute` without `--draft-only` preserves explicit direct publication. See the [automation guide](../../docs/public-sdk-release.en.md#automated-prerelease).

<a id="历史兼容"></a>
## Historical Compatibility

The previous release is fully preserved in the private `weapp-container/runtime-artifacts-private-archive`, while the new, similarly named `runtime-artifacts` retains only the source code for the deprecated tooling. The updated SDK downloader will redirect the nine frozen old version lock identifiers to the private archive and record the actual repository; the old downloader must be upgraded. New versions cannot be created in the old archive, and there is no cross-library rollback. Existing lock files, `ORIGIN.json`, tags, assets, hashes, access permissions, and accompanying licenses remain unchanged. The current migration does not generate or release any new native binaries, nor does it reclassify historical binaries as Apache-2.0.

Verification commands are `pnpm runtime:artifacts:test` and `pnpm sdk:contracts:test` for the root directory. Offline byte validation does not imply true device, GPU, or platform capabilities have been accepted.
