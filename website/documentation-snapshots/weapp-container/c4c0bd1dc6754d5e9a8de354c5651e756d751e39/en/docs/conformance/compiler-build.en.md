The official formal receipt's `compilerBuild` uses `{ path, sha256, bytes }` to reference a standalone build archive. The same 172 cases in a round can share this reference. The reader only depends on the archive content; it can still verify after cleaning the original checkout. `retained-build-inputs.json` continues to be used for diagnostic runtime of copying dist, but does not meet the requirements for formal builds.

```sh
node scripts/conformance-compiler-build.mjs \
  --archive artifacts/conformance-compiler-build/<unique-run> \
  --checkout artifacts/conformance-compiler-build/<unique-run>/checkout \
  --package-manager /absolute/path/to/pinned/pnpm
```

Default source is `vendor/weapp-vite`, commit comes from current baseline. Entry validates the actual HEAD and dirty files of the source code, creates its own detached clone; does not copy the dist, node_modules, or cache from the original directory. The package manager's actual version must match the `packageManager` of the fixed source code; the `pnpm` found via PATH in Turbo subtasks must also come from the same package manager directory and have the same version, to prevent replacement of the fixed tool by Corepack entry in Node directories. Installation uses frozen lock, disables installation scripts, and uses isolated store; build uses Turbo `--force` with a fixed core workspace closure. The build directory and attestation must not exist previously; retries must use a new managed directory.

Archival includes the original Git commit, complete tree, and blob objects. The reader recomputes Git object identities and verifies complete leaf nodes. Git separately records and recomputes CRLF translation for text based on fixed attributes from the original blob. Physical source code content is checked before and after build, so `assume-unchanged` or `skip-worktree` cannot hide modifications.

Snapshot dependencies preserve the content identity, execution bits, and internal links of installed files. Git-tracked `node_modules` test samples are included only within the source code closure and continue to undergo source code integrity checks; they must not be duplicated or overridden in dependency snapshots. The actual pnpm workspace members in the source code determine the direct dependency set; readers require a one-to-one correspondence between declared and parsed records, and recompute parsed results by searching `node_modules` according to the most recent importer. Links pointing outside of checkout, missing targets, cycles, erroneous package names/versions, omitted non-optional dependencies, and borrowing from external store all fail. Original content is preserved in the local `artifacts` CAS, and document and official receipts reference necessary indexes; the entire `node_modules` is not committed to Git.

Before build, the compiler output directory must not exist. Actual installation and build parameters, timestamps, exit status, stdout, stderr, and process results are separately archived; the content of the build artifacts is recorded after build. The `built` label is not accepted in the absence of successful commands, artifacts, source closure, or dependency closure. After build, consumption must also be bound by the runner to the actual compiler file used; a valid but unused build reference cannot substitute for such binding.

The official runner rebuilds independent source code, dependencies, and output closures from the built archive, saving `compilerUse` per case. A fresh compiler entry must be actually loaded; only retained dist, successful exit, or unobserved Vite transform are insufficient.

The new consumption configuration of Enable Macro View stores internally `outputLoadPolicy: "sealed-esm-v1"`. Thus, TSX only transforms the helper functions that still need transformation, and does not rewrite dynamic imports of already-built ESM. Old records without declared policies continue to be validated against the original strict hash. If a finalized product is not accepted by the policy and the actual loaded content changes, it is archived and the byte output is returned for diagnosis, and the acknowledgment continues to fail.

JSON macro new runtime uses a fixed internal `pinned-json-macro-esm-cjs-v4-runtime-input` observation profile; old ESM v2 and CJS v3 validation branches maintain strictness. CJS v4 distinguishes between the full input of the native compiler and the actual output module: it only accepts a fixed 5,878-byte virtual runtime input, a single TypeScript entry output after complete tree-shaking, and zero static external imports and zero dynamic imports. Actual native loading, raw temporary TS, and Node `_compile` consumption CJS bytes are separately validated. Historical blocked receipts are not upgraded upon offline re-reading. Macro evidence traces the step-by-step binding from Vue input before build to actual descriptor, macro evaluation source code, temporary TypeScript, native bundler input/output, output chunk, temporary ESM writes, Node's actual loaded content, and cleanup. The CJS branch only accepts observed, dependency-free `.ts` JSON macros. Preload also captures Node's original `Module.prototype._compile`, separately preserving the physical `evalSource` and the `bundledCode` actually consumed by this function, verifying consistency between the native bundler and the enclosed addon dependencies, and rejecting subsequent transformations, workarounds, fallbacks, URL substitutions, missing consumption, and incomplete restoration.
