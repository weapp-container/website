## Session-held LogManager logs

[`log-manager.js`](../../crates/container-core/src/log-manager.js) provides a standalone runtime factory and four methods, with QuickJS/V8 callbacks writing logs to [`LogManagerJournal`](../../crates/container-core/src/log_manager.rs). Logs do not borrow Console's sixteen-argument, 2048-character formatter, nor do they rely on a writable guest effect/drain global. The session retrieves records from the same native journal and delivers them to existing native SDK Console consumers and Web diagnostics wire; calls that produce logs and calls that fail `toJSON` publicly still reach this drain.

factory and the four members respectively take the minimum level from manifest, trusted host, and provider; no implicit authorization; borrowing the old method cannot bypass revocation. Recording begins after the first successful call to factory. By default, or `{level:0}`, explicit calls, actual App/Page hook, and installed `wx` method calls are recorded; `{level:1}` records only explicit methods. Currently returns a shared Session manager, and subsequent factory calls will update the auto-recording policy. This is the current container policy, not yet proven to match the fixed WeChat version's repeated factory semantics.

Parameter projection preserves the root parameter order, object reference repetition, and cycles, and represents sparse arrays, BigInt, Symbol, Map, Set, ArrayBuffer, special Number types, and own descriptors. Ordinary getters and `toJSON` are not executed; reflection traps of Proxy may still be invoked, thus reentry protection and generation validation at the entry point prevent re-enqueuing after revocation during projection. Isolated surrogates are represented using typed UTF-16 units to avoid silent substitution by Rust/JSON. Projection supports up to 8192 nodes, with a UTF-8 budget of 100 KiB for the final projected JSON; if exceeded, the entire operation is rejected, but health logs can still be written afterward.

native journal retains at most 5 MiB, 8192 volatile records; under pressure, removes the oldest record and reports dropped. Each drain removes at most 128 records, 256 KiB, budget includes diagnostic bridge's second JSON string encoding; unconsumed tail is retained for subsequent host rounds. Enqueued exceptions, poison, and cleanup exceptions are not permitted to pass through the VM ABI; logs cannot replace the return value or exception of the original call.

App hiding, page destruction does not terminate the application-level journal. In the final state, when the application/host calls shutdown, account/service revocation, engine drop, or permanent execution failure occurs, the native owner is shut down and residual records are discarded; thereafter, even if trustworthy capabilities are republished, the incarnation cannot be revived. Implementation is located at [`async_host.rs`](../../crates/container-runtime/src/async_host.rs), [QuickJS execution control](../../crates/container-engine-quickjs/src/execution.rs) and [`EngineTerminalResources`](../../crates/container-core/src/engine_terminal_resources.rs).

Five APIs remain partially implemented: official projection for any value, billing metric of 100 KiB, repeat factory strategy, persistence/upload, and Web/native retention behavior consistency with a fixed WeChat version are not completed. The current diagnostic consumer has not passed the WeChat Log Service acceptance.

## Immutable byte owner of BufferURL and image consumption

[`buffer-url.js`](../../crates/container-core/src/buffer-url.js) Sync receives nine kinds of TypedArray from ArrayBuffer and locked declarations, taking snapshots of bytes according to their real `byteOffset/byteLength`. DataView, BigInt TypedArray, shared buffers, forged receiver, detached and over-budget inputs are explicitly rejected. create/revoke independent access, private native callback is removed from global after bootstrap, generic host descriptor cannot replace these two runtime APIs.

[`BufferUrlStore`](../../crates/container-core/src/buffer_urls.rs) assigns a native 192-bit random identity at runtime, with bytes as immutable Arc; identical content still receives different URLs. Maximum 8 MiB per lease, 32 MiB per owner, 1024 leases total. `revokeBufferURL` synchronously returns void, removing only the lease associated with the current owner's address; revoking, unknown, or other owners' URLs does not affect the valid resource. Limits and URL forms are container policies and cannot be used to claim the complete official parameter space.

The current consumption chain currently covers PNG, JPEG, WebP for `<image>`. [`buffer_urls.rs`](../../crates/container-runtime/src/buffer_urls.rs) generates a View resource descriptor from a live lease of the same Session; [`images.rs`](../../crates/container-runtime/src/images.rs) revalidates the lease before accessing each frame resource and decoded cache, and identical content hashes do not substitute authorization. Preview uses the byte owner of a live Session, and page/component reconstruction does not alter resource ownership.

Web direct/WASM and production Worker/DOM read resources via [`browser_view_resource_at_path`](../../crates/container-runtime/src/browser_view.rs) using the complete presentation key, exact descriptor path, SHA-256, and size. The Worker's [`resource` RPC](../../examples/hosts/web-wasm/worker-runtime.mjs) retains the path, while the [DOM adapter](../../examples/hosts/web-wasm/worker-dom-adapter.mjs) validates receipts and actual digest before creating a Blob URL. Dynamic resources do not permit rollback via digest-only read paths; previous surfaces, addresses after undo, and addresses after owner change are no longer authorized for new reads.

Application hiding and Page retirement retains application-level tenancy. Final-state application unloading, service/account revocation, terminal host-call shutdown, native engine drop/permanent failure will empty the owner, and cleanup must occur even if public revoke is denied. Immutable frame or DOM Blob lease that has been successfully published is retained according to the existing last user's lifecycle; revocation does not retroactively clear already published pixels, and new resource reads and cache usage must pass through the gate again.

Two APIs continue Partial. Currently, there is no official proof of the complete lifecycle/limit semantics for URL, nor has the image consumer been extended to audio, video, files, or other media APIs; these consumers must be implemented and accepted separately. Limited QuickJS/WASM image execution cannot replace public SDKs across seven endpoints, other engines/OS, physical devices, or acceptance from WeChat oracle.

## Independent Admission for Lifecycle Notifications

[`lifecycle-notifications.js`](../../crates/container-core/src/lifecycle-notifications.js) preserves private grants for `on/offAppShow`, `on/offAppHide`, `on/offBeforePageUnload`, `on/offAfterPageUnload`; Session first retrieves the manifest declaration of the method, then computes the minimum level with a trusted host/provider, retaining Partial, without relying on counterpart authorization. Neither the direct nor counterpart descriptor of a generic installer can override these methods, and modifying the public capability map does not grant permissions.

Revoke a specific on method only removes the corresponding event listener and increments the generation, truncating the captured but unexecuted tail; reauthorization does not replay old subscriptions. Standard off still proceeds according to the existing emission snapshot and is not equivalent to trusted revocation. Notification admission does not delete internal departure/receiver states, so before/after can continue pairing and complete actual page retirement; rejection of public show/hide listeners also does not cancel the scheduler's pause/resume. Final state retire clears all listeners and pending departures, independently of public off permissions. This is a boundary fix for existing notification implementations, without increasing the available in this batch.

## File Text Encoding and UTF-16 Boundaries

[`host-bridge.js`](../../crates/container-core/src/host-bridge.js) projects the original JS string character by code unit into a private `__weappSyncText` before it enters Rust JSON via `writeFileSync`, `appendFileSync`, and `writeSync`, and serializes it only once. The actual ArrayBuffer continues along the binary path; `readSync` still modifies and returns the original buffer to the caller. The private marker is not a new public input type, and forged ordinary objects or TypedArray writes do not gain support as a result.

[`sync_file_codecs.rs`](../../crates/container-runtime/src/sync_file_codecs.rs) supports all 11 alias names with locking: `ascii`, `base64`, `binary`, `hex`, `ucs2`, `ucs-2`, `utf16le`, `utf-16le`, `utf-8`, `utf8`, `latin1`. Actual disk and descriptor I/O use the same codec. UTF-8 replacement, ASCII read high-bit mask, hex truncation, Base64 whitespace/URL alphabet, and UTF-16LE odd-byte handling are implemented against Node Buffer limited vectors and cannot replace the official WeChat semantics.

Shared managed-file owner's text read retention code-unit wire: synchronous `readFileSync` restored at guest return point, asynchronous managed-file `readFile` restored at guest-facing `result.data`. Rust/JSON hop does not prematurely convert isolated surrogates from UTF-16LE to Unicode scalar; Harmony unit tests directly assert private units, live FFI tests validate guest results for synchronous writes and asynchronous reads. This fix does not extend async write's lone-surrogate input domain, nor does it fix Storage's full UTF-16/JSON domain.

Four synchronous producers continue Partial on 24 units of six native hosts. The managed-user path, single-block/JSON/owner budget, remaining locked parameters, cross-owner quota, and public SDK acceptance are still retained separately; Web synchronous file persistence has not been advanced by native `std::fs`.
